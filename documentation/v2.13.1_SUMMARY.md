# AWS HTML Report Generator - Version 2.13.1

## Summary
Fixed field name bugs in ECS and EKS sections - now correctly uses field names from verification output (ServiceDetails, ClusterName, etc.). Removed Load Balancers (they have their own section).

## What Changed

### Bug Fixes

**ECS Services Issue:**
- ❌ Was using `cluster.get('Services')` - this is an integer count
- ✅ Now uses `cluster.get('ServiceDetails')` - the actual service list
- Added `isinstance(services, list)` check for safety

**ECS Cluster Properties:**
- Fixed field names to match verification output:
  - `RegisteredInstances` (not `RegisteredContainerInstancesCount`)
  - `RunningTasks` (not `RunningTasksCount`)
  - `PendingTasks` (not `PendingTasksCount`)
  - `Services` (the count, now correctly used)

**EKS Cluster Properties:**
- Fixed field names to match verification output:
  - `ClusterName` (not `Name`)
  - `VPC` (not `VpcId`)
  - Removed `PlatformVersion` (not in verification data)

**Load Balancers:**
- Removed from Compute section
- They have their own separate `verify_load_balancers()` section

## Data Structure (from verification script)

### ECS Format:
```python
{
  'ClusterName': 'production',
  'Status': 'ACTIVE',
  'RegisteredInstances': 5,
  'RunningTasks': 10,
  'Services': 3,  # Integer count
  'ServiceDetails': [  # Actual list
    {
      'ServiceName': 'web-service',
      'Status': 'ACTIVE',
      'DesiredCount': 2,
      'RunningCount': 2,
      'LaunchType': 'FARGATE'
    }
  ]
}
```

### EKS Format:
```python
{
  'ClusterName': 'prod-eks',
  'Version': '1.28',
  'Status': 'ACTIVE',
  'Endpoint': 'https://...',
  'VPC': 'vpc-xxx'
}
```

## New Sections

### 1. ECS Clusters and Services

Shows detailed information for each ECS cluster:

**Cluster-level information:**
- ARN
- Status
- Registered Container Instances
- Running Tasks count
- Pending Tasks count  
- Active Services count

**Service-level table (per cluster):**
| Service Name | Status | Desired | Running | Pending | Launch Type |
|--------------|--------|---------|---------|---------|-------------|
| service-1    | ACTIVE | 2       | 2       | 0       | FARGATE     |

**Features:**
- Each cluster gets its own h4 heading
- Cluster properties in dedicated table
- Services shown per cluster with color-coded status badges
- ✅ Green badge for ACTIVE services
- ⚠️ Yellow badge for other states

### 2. EKS Clusters

Simple table showing all EKS clusters:

| Cluster Name | Status | Version | Endpoint | Platform | VPC |
|--------------|--------|---------|----------|----------|-----|
| prod-eks     | ACTIVE | 1.28    | https... | eks.1    | vpc-xxx |

**Features:**
- Color-coded status badges (ACTIVE = green)
- Kubernetes version
- API endpoint
- Platform version
- VPC association

### 3. Load Balancers (ALB/NLB)

Comprehensive table of all load balancers:

| Name | Type | Scheme | State | VPC | AZs | DNS Name |
|------|------|--------|-------|-----|-----|----------|
| prod-alb | application | internet-facing | active | vpc-xxx | 3 | prod-alb-123.elb... |

**Features:**
- Shows both ALB (Application) and NLB (Network) load balancers
- Color-coded scheme badges:
  - ⚠️ Yellow for internet-facing (higher visibility)
  - 🔵 Blue for internal
- State badges (active = green)
- Availability Zone count
- Full DNS name for connection
