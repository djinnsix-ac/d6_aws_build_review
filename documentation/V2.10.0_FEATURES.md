# Version 2.10.0 - Enhanced Network Visualization

## New Features

### 1. ✅ VPC Grouping (Visual)
- Nodes are color-coded by their VPC
- Security groups from the same VPC naturally cluster together via force simulation
- Red border on nodes with permissive rules

### 2. ✅ Node Sizing by Rule Count
- **Bigger nodes** = More rules (ingress + egress combined)
- Size range: 10px (few rules) to 30px (many rules)
- Makes it easy to spot "busy" security groups
- Example: A node with 20 rules will be visibly larger than one with 2 rules

### 3. ✅ Egress Flow Visualization
- **Green arrows** show egress (outbound) connections
- **No arrows** = ingress (inbound) connections
- Toggle on/off with **"Show Egress"** checkbox
- Previously only showed ingress, now shows full bidirectional flow

### 4. ✅ All Ports/All Protocols Highlighting
- **Dashed animated edges** = Overly permissive rules (all ports or all protocols)
- **Thicker lines** (4px vs 2px) for visibility
- **Red border on nodes** that have ANY permissive rules
- Click **"Show Overly Permissive"** button to filter to just these
- Tooltip shows ⚠️ warning when hovering

### 5. ✅ Port Filtering
- New input box: Enter port numbers (e.g., "22, 443, 3389")
- Click **"Apply"** to show only connections using those ports
- Great for:
  - "Show me all SSH access" → Enter "22"
  - "Show me all web traffic" → Enter "80, 443"
  - "Show me all RDP access" → Enter "3389"

## What Each Feature Looks Like

### Node Sizing
```
Small node (10px radius):
  ○ sg-lambda (2 rules)

Medium node (20px radius):
  ◉ sg-app-tier (10 rules)

Large node (30px radius):
  ⬤ sg-database (25 rules)
```

### Permissive Rule Indicators
```
Normal rule:
  [SG-A] ——————> [SG-B]  (solid green line, 2px)

Permissive rule (all ports):
  [SG-A] = = = > [SG-B]  (dashed green line, 4px, animated)
                          Red border on both nodes
```

### Egress vs Ingress
```
Ingress (inbound):
  [SG-A] ——————— [SG-B]  (no arrow)

Egress (outbound):
  [SG-A] ————→ [SG-B]  (green arrow at end)
```

### Port Filtering Example
```
Before filter:
  [SG-ALB] —443→ [SG-App] —5432→ [SG-DB]
  [SG-Bastion] —22→ [SG-App]

After entering "22" in port filter:
  [SG-Bastion] —22→ [SG-App]  (visible)
  (other connections faded)
```

## Technical Details

**New Node Properties:**
- `totalRules` - Sum of ingress + egress count (used for sizing)
- `hasPermissiveRules` - Boolean, true if ANY rule is all-ports/all-protocols

**New Link Properties:**
- `direction` - 'ingress' or 'egress'
- `isPermissive` - Boolean, true if rule is all-ports or all-protocols

**Permissive Detection Logic:**
```javascript
// A rule is permissive if:
rule.IpProtocol === '-1'  // All protocols
|| !rule.FromPort         // No port specified
|| portRange === 'All'    // Explicitly marked as "All"
```

**Node Sizing Formula:**
```javascript
radius = Math.min(30, 10 + totalRules)
// Examples:
//   0 rules  → 10px
//   10 rules → 20px
//   20+ rules → 30px (capped)
```

## Known Behaviors

- **Egress arrows** may overlap with nodes, adjust by dragging
- **Large graphs** (50+ SGs) may be cluttered - use filters
- **Port filter** is substring match, so "22" matches "22", "222", "1022"
- **Permissive detection** is conservative - catches "-1" protocol and null ports
