# Version 2.3.2 - VPC Peering Collection Fix

## Bug Fixed ✅

**Problem**: VPC Peering connections only collected when the VPC was the **requester**, not when it was the **accepter**.

**Example**: Your `insights-xtribe-peering-prep` connection shows:
- Requester VPC: `vpc-076d8154ea7d39807` (in Ireland)
- Accepter VPC: `vpc-0da83feb5d4db29b7` (your VPC)

The old code only looked for peering where your VPC was the requester, so it missed this connection.

**Fixed**: Now collects peering connections where the VPC is either requester OR accepter, then deduplicates.

## Code Change

**Before** (v2.3.1):
```python
peering = ec2.describe_vpc_peering_connections(
    Filters=[
        {'Name': 'requester-vpc-info.vpc-id', 'Values': [vpc_id]},
    ]
)['VpcPeeringConnections']
```

**After** (v2.3.2):
```python
# Get connections as requester
peering_as_requester = ec2.describe_vpc_peering_connections(
    Filters=[
        {'Name': 'requester-vpc-info.vpc-id', 'Values': [vpc_id]},
    ]
)['VpcPeeringConnections']

# Get connections as accepter
peering_as_accepter = ec2.describe_vpc_peering_connections(
    Filters=[
        {'Name': 'accepter-vpc-info.vpc-id', 'Values': [vpc_id]},
    ]
)['VpcPeeringConnections']

# Combine and deduplicate
peering_ids = set()
peering = []
for p in peering_as_requester + peering_as_accepter:
    if p['VpcPeeringConnectionId'] not in peering_ids:
        peering_ids.add(p['VpcPeeringConnectionId'])
        peering.append(p)
```
