# Version 2.11.5 Summary - Rule Display & VPC Endpoint Tooltip Fixes

## Changes

### 1. Security Group Rule Display - Each Destination is Now a Separate Numbered Rule ✅

**Problem**: When a security group rule had multiple destinations (e.g., 2 prefix lists), they were shown as:
```
Protocol: tcp | Port: 443 | Destination: pl-6fa54006 (DynamoDB Gateway Egress)
pl: pl-6da54004 (S3 Gateway Egress)
```

**Solution**: Each destination is now a distinct, numbered rule:
```
Rule 1: Protocol: TCP | Port: 443 | Destination: pl-6fa54006 (DynamoDB Gateway Egress)
Rule 2: Protocol: TCP | Port: 443 | Destination: pl-6da54004 (S3 Gateway Egress)
```

**Why This Matters**:
- Matches how AWS console displays rules
- Matches how the verification script counts rules
- Makes it crystal clear that these are 2 separate permission entries
- Each IP range, SG reference, IPv6 range, and prefix list gets its own numbered entry

### 2. VPC Endpoint Tooltip Improvements ✅

**Changes Made**:
- **Service Name Extraction**: 
  - Removes `com.amazonaws.eu-west-1.` prefix from descriptions
  - Converts "DynamoDB Gateway Egress" → "DynamoDB Endpoint"
  - Converts "S3 Gateway Egress" → "S3 Endpoint"
  - Shows clean service names instead of raw prefix list IDs

- **Bulleted Source List**:
  - Sources are now listed with bullet points on separate lines
  - Much easier to read when multiple security groups connect to the same endpoint

**Before**:
```
VPC Endpoint
Prefix List: pl-6da54004
Connections: 7
Sources: dtpl-sagemaker-endpoints-sg01, Glue security group, dtpl-sagemaker-jobs-sg02, ...
```

**After**:
```
S3 Endpoint
Prefix List: pl-6da54004
Connections: 7
Sources:
• dtpl-sagemaker-endpoints-sg01
• Glue security group
• dtpl-sagemaker-jobs-sg02
• dtpl-insights-prep-airfactory-workload-sg-20240322105710410200000018
• ecs_security_group
• dtpl-insights-prep-sagemaker-workload-sg-20240322105710478800000019
• dtpl-insights-prep-lambda-function-sg-20240322105710258000000016
```

## Technical Details

### Code Changes

**`format_security_group_rule()` function**:
- Completely rewritten to iterate through each destination type
- Each IP range, SG reference, IPv6 range, and prefix list creates a separate numbered rule entry
- Compliance badges and issues are shown appropriately for each rule
- Issues/recommendations only displayed once (on first rule) to avoid repetition

**Prefix List Node Creation**:
- Captures `plDescription` from security group rule data
- Stores description in a map when creating links
- Processes description to extract clean service name
- Node `name` property now shows service name instead of prefix list ID

**VPC Endpoint Tooltip**:
- Uses the processed service name as the tooltip title
- Formats source list with bullet points and line breaks
- Shows prefix list ID as secondary information
