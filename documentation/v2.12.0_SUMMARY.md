# Version 2.12.0 & 2.3.1 Summary - VPC Endpoints & Peering

## Two Files Updated ✅

### 1. aws_build_review-v2.3.1.py - Data Collection
**Added**: VPC Endpoints collection

**Change**: One new API call per VPC:
```python
vpc_endpoints = ec2.describe_vpc_endpoints(
    Filters=[{'Name': 'vpc-id', 'Values': [vpc_id]}]
)['VpcEndpoints']
```

**Why**: VPC Endpoints weren't being collected before, so they couldn't be displayed in reports.

### 2. generate_html_report-v2.12.0.py - Report Generation
**Added**: Complete VPC Endpoints and VPC Peering sections with drill-down

## What's New

### VPC Endpoints Section
Shows all VPC Endpoints in each VPC with:
- Summary table with Endpoint ID, Service Name, Type, State
- Click "View Details" to expand full configuration
- Drill-down shows:
  - Service name, type, state
  - Private DNS enabled/disabled
  - Associated route tables (Gateway endpoints)
  - Associated subnets (Interface endpoints)
  - Security groups attached
  - Network interface IDs
  - DNS entries
  - Policy document (formatted JSON)
  - Tags

**Example Display**:
```
VPC Endpoints (3)
┌────────────────────────────────────────────────────────────────┐
│ Endpoint ID  | Service Name    | Type      | State     | Details│
├────────────────────────────────────────────────────────────────┤
│ vpce-xxx     | S3              | Gateway   | available | View   │
│ vpce-yyy     | DynamoDB        | Gateway   | available | View   │
│ vpce-zzz     | ec2messages     | Interface | available | View   │
└────────────────────────────────────────────────────────────────┘
```

### VPC Peering Connections Section
Shows all VPC Peering connections with:
- Summary table with Peering ID, Requester VPC, Accepter VPC, Status
- Click "View Details" to expand full configuration
- Drill-down shows:
  - Status and message
  - **Requester VPC details**: VPC ID, CIDR, Owner, Region, IPv6
  - **Accepter VPC details**: VPC ID, CIDR, Owner, Region, IPv6
  - **Peering options**: DNS resolution settings (both directions)
  - Tags

**Example Display**:
```
VPC Peering Connections (2)
┌────────────────────────────────────────────────────────────────────────────┐
│ Peering ID | Requester VPC        | Accepter VPC         | Status | Details│
├────────────────────────────────────────────────────────────────────────────┤
│ pcx-xxx    | vpc-111              | vpc-222              | active | View   │
│            | 10.0.0.0/16          | 10.1.0.0/16          |        |        │
└────────────────────────────────────────────────────────────────────────────┘
```

## Key Features

### VPC Endpoints
- **Gateway vs Interface**: Clearly distinguished
  - Gateway: Shows route table associations
  - Interface: Shows subnet/ENI associations
- **DNS Configuration**: Shows if private DNS is enabled
- **Security**: Shows attached security groups (Interface endpoints)
- **Policy**: Full IAM policy document displayed (formatted JSON)

### VPC Peering
- **Cross-account**: Shows owner IDs for both requester and accepter
- **Cross-region**: Shows regions for both VPCs
- **CIDR blocks**: Shows IPv4 and IPv6 CIDRs
- **DNS resolution**: Shows if DNS resolution is enabled in each direction
- **Status tracking**: Active, pending-acceptance, failed, etc.

## Upgrade Path

**You need to run ALL THREE scripts**:
```bash
# Step 1: Collect data with VPC Endpoints (NEW VERSION)
python3 aws_build_review-v2.3.1.py --output collected_data.json

# Step 2: Verify (no changes needed)
python3 aws_build_verification-v2.5.2.py --input collected_data.json --output verification.json

# Step 3: Generate report with VPC Endpoints/Peering sections (NEW VERSION)
python3 generate_html_report-v2.12.0.py --input verification.json --output report.html
```

**Important**: You MUST re-run data collection (step 1) to get VPC Endpoints. Old collected data won't have them.

## IAM Permissions Required

The data collection script now needs:
```json
{
  "Effect": "Allow",
  "Action": [
    "ec2:DescribeVpcEndpoints"
  ],
  "Resource": "*"
}
```

VPC Peering already works (describe-vpc-peering-connections permission already in use).

## What You'll See

When you open the HTML report:
1. Navigate to "VPC Architecture" section
2. Each VPC will show:
   - Existing configuration summary
   - **NEW**: VPC Endpoints table (if any exist)
   - **NEW**: VPC Peering Connections table (if any exist)
3. Click "View Details" on any endpoint or peering to see full config
4. Endpoints show whether they're Gateway (for S3/DynamoDB) or Interface (for other services)
5. Peering shows both VPCs involved, their CIDRs, and cross-account/region details
