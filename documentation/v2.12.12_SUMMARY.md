### Style Changes

**VPC Endpoints & VPC Peering now use h5 styling:**
- Font size: 18px → **15px**
- Color: #667eea (purple) → **#2c5aa0 (blue)**
- Border: 3px solid → **removed**

Matches Configuration, Subnet Distribution, and Route Tables styling.

## Rationale

VPC Endpoints and VPC Peering are **VPC-specific resources** that belong to individual VPCs, just like:
- Configuration (VPC settings)
- Subnet Distribution (subnets in that VPC)
- Route Tables (route tables for that VPC)

They should NOT be at the same level as:
- VPC name heading (h4)
- Network ACLs heading (h4 - shows ALL NACLs across ALL VPCs)

## Visual Hierarchy

### Correct Structure
```
VPC Architecture [h2]
│
├─ ► VPC: vpc-name-1 (vpc-xxx) [h4, purple, 18px]
│   ├─ ► Configuration [h5, blue, 15px]
│   ├─ ► Subnet Distribution [h5, blue, 15px]
│   ├─ ► Route Tables [h5, blue, 15px]
│   ├─ ► VPC Endpoints [h5, blue, 15px] ✅ Same level as Route Tables
│   └─ ► VPC Peering [h5, blue, 15px] ✅ Same level as Route Tables
│
└─ ► Network ACLs (2) [h4, purple, 18px] ← Cross-VPC section
```

### Heading Levels Explained
- **h2** = Major sections (VPC Architecture, Security Groups, etc.)
- **h4** = VPC names & cross-VPC sections (Network ACLs)
- **h5** = VPC-specific subsections (Config, Subnets, Routes, Endpoints, Peering)

## About Default NACLs

**Question:** "How can both NACLs be default?"

**Answer:** Each VPC gets its own default NACL when created. Looking at your screenshot:
- NACL `acl-01b1b143d81462ad9` is the default for VPC `vpc-053bb47a615ba4bb9`
- NACL `acl-064b44ac4741b328b` is the default for VPC `vpc-03269d2d04b8dd4e9`

The "Default" column indicates if a NACL is the default for **its VPC** (shown in VPC ID column), not for the account. Every VPC has exactly one default NACL.
